# Documentation and Contribution Guidelines

## Markdown

- Use lowercase kebab-case for new filenames.
- Use one clear H1 heading per document.
- Keep technical claims precise and distinguish observations from conclusions.
- Use relative links and verify that every referenced file exists.

## Writeups

A practical writeup should normally contain objective, scope/authorization, environment, methodology, evidence, interpretation, defensive/detection angle, key takeaway and cleanup where applicable.

Never publish real credentials, private keys, tokens, flags, personal identifiers or unredacted private network information.

## Notes

Topic notes should be self-contained. Source images may be retained for traceability, but the final explanation should not require opening those images.

## Detection rules

Every published detection should identify its telemetry, behavior, rationale, false-positive considerations, ATT&CK mapping where appropriate, and actual test result.

Do not label a rule "tested" unless it was actually executed against representative telemetry.

## Offensive-security material

Only use authorized targets, intentionally vulnerable labs, CTF environments or systems for which explicit permission exists.
