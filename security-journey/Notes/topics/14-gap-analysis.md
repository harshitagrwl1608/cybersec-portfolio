# Gap Analysis

## Overview
Gap analysis compares the current security state with a desired target state. The gap is not simply a list of failures; it identifies which controls, capabilities, processes, or evidence must be added or improved to reach the target.

## Core concepts
- Define the target state first.
- Collect evidence about the current state.
- Map current controls to requirements.
- Identify and prioritize gaps by risk, impact, cost, and dependency.
- Create a remediation plan with owners and dates.

## Practical examples
- A gap analysis might show that MFA exists for administrators but not standard users, creating a specific control gap against the target policy.

## Security / mitigation
- Use measurable requirements and evidence, not assumptions.
- Reassess after remediation to confirm the gap actually closed.

## Detection / troubleshooting
- Audit findings, missing logs, control failures, and policy exceptions are common evidence sources.
